SONICFRAME LOGIN SETUP  (about 5 minutes, free)
================================================
Login uses Google Firebase Authentication: email + password, and "Continue with Google".
Studio, Motion, Foley, Timeline, Mixer and AI Co-Pilot are locked until a user signs in.
Only index.html (the landing page) is public.

1. Go to https://console.firebase.google.com  ->  Add project (Analytics not needed).

2. Build -> Authentication -> Get started -> Sign-in method tab:
     - Enable "Email/Password"
     - Enable "Google" (choose a support email, Save)

3. Project settings (gear icon) -> General -> "Your apps" -> click the Web icon </>
   -> register an app (any name). Copy the firebaseConfig values.

4. Open firebase-config.js and paste apiKey, authDomain, projectId, appId.
   (These are not secrets; they are meant to be in front-end code.)

5. Authentication -> Settings -> Authorized domains -> Add domain:
     your-site-name.netlify.app   (and your custom domain, if you have one)
   "localhost" is already allowed for testing.

6. Deploy the whole folder to Netlify (drag and drop). Keep all files together.

TESTING LOCALLY
Do not double-click the HTML files. Sign-in does not work from file://.
Run a local server inside the folder instead, then open http://localhost:8000
     python -m http.server 8000

OPTIONS (firebase-config.js)
REQUIRE_EMAIL_VERIFICATION = true  -> email users must click the link in the
verification email before they can enter (Google users are already verified).
Set to false to let email users in straight after registering.

PASSWORD ATTEMPT LIMITER
After 5 wrong passwords for the same email address, sign-in is blocked for 5
minutes. The count and the lock expiry are kept on the server in Netlify Blobs
(no setup needed; it is included with Netlify Functions), so reloading the page,
reopening the browser or coming back later does not clear them. The countdown in
the login box is only a display of the server's remaining time.
The site calls /.netlify/functions/login-attempts. To test locally you need
Netlify Functions running, so use:
     npx netlify-cli dev
(plain "python -m http.server" serves the pages but has no function, so sign-in
works there WITHOUT any attempt counting or countdown).

If the countdown never appears, open the browser console and the Network tab.
The POST to /.netlify/functions/login-attempts tells you which part is missing:
  404 -> the function was not deployed (redeploy it, see the note below)
  503 -> Netlify Blobs is not available to the function
  no request at all -> an older cached copy of sonicframe-auth.js is being served
Deploy with "npx netlify-cli deploy --prod" or via a Git-connected site. Do not
drag and drop the folder for this change: manual deploys skip the build command,
so @netlify/blobs is not installed for the function.
One limit worth knowing: Firebase checks the password in the browser, so the
limiter counts attempts made through this login form. Someone calling Firebase's
API directly, bypassing the site, is subject to Firebase's own rate limits
instead. Real server-only enforcement would need the Firebase Admin SDK and a
service account.

PASSWORD STORAGE: HASHING & SALTING
Passwords are NOT stored by SonicFrame's codebase, Netlify functions, or localStorage.
All authentication credentials are processed by Google Firebase Authentication:
  1. Transmission: Credentials travel encrypted over TLS directly to Google's
     Identity Platform endpoints (identitytoolkit.googleapis.com).
  2. Salting: Google generates a unique, cryptographically random salt for each user.
  3. Hashing: Google hashes the password using its hardened, modified scrypt
     algorithm (combining per-user salts, project salt separators, rounds, and
     signer keys). Plaintext passwords are never stored in the database.
  4. Attempt Tracking: The rate limiter stores only attempt counts, timestamps, and
     SHA-256 hashed email keys—passwords are never passed to or stored by the limiter.

IMPORTANT: WHAT THIS DOES AND DOES NOT PROTECT
The lock hides the pages and features from anyone not signed in. Because this is a
static site, the HTML files themselves can still be downloaded by someone who knows
the URL. That is fine for a UI lock, but anything that must be truly private (such
as your AI API key and usage) must be checked on the server. The AI Co-Pilot already
sends the signed-in user's Firebase ID token to your endpoint as
"Authorization: Bearer <token>". Verify it there with the Firebase Admin SDK
(verifyIdToken) and reject requests without a valid token.

DEPLOYING TO NETLIFY (frontend only)
1. Unzip SONICFRAME.zip. Open https://app.netlify.com/drop
2. Drag the unzipped SONICFRAME folder (the one that directly contains index.html)
   onto the page. Do not drag the zip, and do not drag a folder that contains it.
3. Netlify gives you a URL like https://random-name.netlify.app. Optional: Site
   configuration -> Change site name.
4. Copy that domain (without https://) into Firebase -> Authentication ->
   Settings -> Authorized domains -> Add domain. Google/email login will not
   work on the live site until this is done.
5. Open the live URL, register, and test. To update later, drag the folder again
   (Deploys tab -> drag and drop) or connect a GitHub repo for automatic deploys.
Included netlify.toml adds basic security headers and makes sure updates show
immediately.
